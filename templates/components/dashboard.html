      Developer Integration — Local Python SDK & CLI

      Already have your own healthcare AI model? Run Asclepius locally using the Python SDK.

      In-Situ Evaluation

      Your model and evaluation data remain in your environment. Asclepius audits your fitted scikit-learn models directly in memory with zero remote telemetry or external data transfer.

      # Install & run in your local Python environment:
      from asclepius import FairAIAuditor

      auditor = FairAIAuditor(
        model=my_fitted_model,
        X_test=X_test,
        y_test=y_test,
        sensitive_features=X_test["sex"],
        target_name="readmitted_30d",
        sensitive_name="sex"
      )
      result = auditor.run()
      print(result.summary())
      result.generate_report("audit_report.pdf")
      CLI also available: asclepius audit --demo or asclepius audit --data evaluation.csv. See docs/SDK_GUIDE.md for full reference.

      Clinical Impact: Why False Negative Rate Matters

      Healthcare-specific algorithmic fairness considerations

      In healthcare AI, algorithmic bias often manifests as an uneven False Negative Rate (FNR) across demographic groups.

      Clinical Disparity Indicator:

      A higher false-negative rate for one subgroup means the model is missing more positive disease/risk cases in that group relative to others. This is a model-level disparity signal that warrants clinical review and threshold calibration.

      Metric differences alone do not prove clinical harm or intent; they serve as quantitative screening triggers for safety and equity audits.

      Model Internals Withheld

      External Model Audit received held-out prediction evidence, but the original model internals and feature-level inputs were not provided. Therefore, feature-level SHAP attribution cannot be calculated without making unsupported assumptions.

      Available Evidence

      • Ground-truth labels (y_true) — Verified clinical outcomes
      • Model predictions (y_pred) — Binary risk classifications
      • Prediction probabilities (y_prob) — Confidence scores, when supplied
      • Sensitive-group information — Protected attribute cohorts

      Unavailable

      • Original model object — Fitted pipeline withheld by external vendor
      • Model architecture / parameters — Estimator parameters, weights, trees
      • Feature-level model inputs — Clinical features used during inference
      • Feature-level SHAP attribution — Game-theoretic Shapley contributions
      • Individual feature contribution — Per-variable patient attributions
      Pipeline Mode Distinction:
      • Local Model Mode: Actual model available → TreeExplainer / LinearExplainer calculates full global and patient-level SHAP attributions.
      • External Model Audit Mode: Only prediction evidence available → feature-level SHAP is withheld to prevent unscientific fabrication.

      Protected Attribute Transparency

      Tracking demographic variable exposure

      The sensitive attribute status is evaluated against the model's feature space.

      Model Feature Policy:

      Omitting protected variables (e.g. race or gender) does not automatically prevent algorithmic bias due to correlation proxies (e.g. zip code, clinical comorbidities, insurance type).

      Clinical Interpretation & Non-Causality

      Distinguishing correlation from medical etiology

      SHAP feature attributions reflect statistical associations within this trained classifier. They do not establish biological or clinical causation.

      Fairness vs Explainability:

      SHAP explains how the algorithm arrived at its prediction, but it does not prove why demographic disparities exist. Fairness must always be evaluated using rigorous group disparity metrics (e.g. DPD, Equal Opportunity, Underdiagnosis FNR).
